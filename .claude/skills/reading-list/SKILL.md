# 代码精读清单维护(docs/08-代码精读清单.md)

清单定位:值得**逐行精读**的代码/设计索引,不是全量目录。简单 CRUD(八件套产物)、纯样板复制不入册。
docs/08 为作者个人学习笔记,**不随仓库发布**(见 TODO.md #15 商密边界)。

## 登记(新增条目)

1. **定锚**:用 Grep 找到目标方法声明的**真实行号**,禁止凭记忆写行号。锚 = 方法声明行,同时记下方法名(行号漂移时的兜底定位)。
2. **写条目**,格式对齐清单内已有条目:
   - 标题一句话说明设计意图;
   - `[方法名](repo 相对路径)` markdown 链接 + ` :行号` + 方法名文本(路径一律正斜杠;⚠️ 不用 `#L行号` 片段——IDEA 原生不支持链接跳行,IJPL-93490 未实现);
   - 「读时自问」2~4 条:写**为什么这么写、换个写法会怎样**,不复述 docs/07 已有规约;
   - 配套引用(强关联的 Mapper XML / 测试 / 配置)同样带 `路径:行号`;
   - 标注来源(TODO 编号或 commit 主题)。
3. **归组**:并发与锁 / 幂等与数据一致性 / 安全 / 模型与装配 / 防腐与翻译 / 工具链;新主题可加组,组内重排编号。
4. **去重**:登记前先通读 docs/08,确认该学习点未收录;一条只讲一个学习点。

## 校准(行号防漂移)

- 用户说「校准/整理清单」时:逐条 Grep 方法签名,更新行号;代码已删除的条目直接移除并告知。
- 大规模重构落地(如 commit 触及 10+ 文件、codegen 模板改版)后,主动提议跑一次校准——「保护逻辑编码在 SQL 列清单/XML 里」这类条目优先核对。

## 纪律

- **信噪比优先**:总条目控制在 15 上下;过时、或要点已被 docs/07 吸收的条目删除。
- 时机:提交前自查(self-review)发现亮点、或人工拍板了一个非显然的设计决策时,主动提议「这条值得进 docs/08」,由用户确认后登记。
- 顺手维护:改到清单内已收录的代码时,检查行号是否漂移,漂移即改。
- **格式定格**:条目定位 = markdown 链接(点击开文件)+ ` :行号` 文本(`Ctrl+Shift+N 文件名:行号` 落行);IDEA 原生不支持链接带 `#L行号` 片段跳转(IJPL-93490 未实现),File Link Navigator 插件已评估弃用(兼容上限 251.* 且只解析 Java 注释),勿再尝试。
