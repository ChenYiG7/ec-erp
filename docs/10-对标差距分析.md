# 10 对标差距分析(2026-09-09 调研快照)

> 结论先行:本系统在**单条业务链路的工程深度**(库存动账/成本账/状态机守卫/AI 工程化)与**AI 能力完整度**上已达到或超过三个开源对标;差距集中在**平台覆盖面、广告域、财务深水区、履约形态、监控面、移动端**六处,其中前两处被真凭证/资质外部依赖阻塞,后四处属功能广度缺口。商业产品(领星/优麦云)的完整度差距本质是**团队规模与商业化年限**的差距,对标取其功能形态做 roadmap,不追其覆盖面。
>
> 调研口径:wimoor/OmniTradeERP/qihang-erp-open 按仓库 README 与官网功能清单(2026-09-09 复核,许可纪律见 §6);领星/优麦云为闭源 SaaS,按官网/百科功能宣传对标,无代码可参考。

## 3. 本系统的差异化价值(对标中站得住的部分)

1. **技术栈代差优势**:Boot 4.0.6 + Spring AI 2.0.1 GA + AgentScope 2.0.2 GA + JDK 21 三层 AI 叠加,为开源对标中最完整(wimoor 停在 JDK8/SB2,OmniTrade 无 Agent 层,qihang 已追到 Boot 4.1 但 AI 面为单层 Tool)。
2. **架构纪律**:防腐层 SPI + 契约模块收口跨域 + 条件更新即守卫 + 唯一入口动账 + upsert 幂等 + AFTER_COMMIT 事件编排——这套纪律在开源对标中未见同等显式约定(OmniTrade 有硬编码模拟前科,wimoor 1688 镜像表族被本项目判定为过度设计)。
3. **AI 工程化质量**:判断归 AI、执行归程序;AI 产出一律落建议表人工确认(不给写库);只读工具红线;工具调用审计行;三重降级分级语义(建议本体可信来源分派)。qihang 的读写 Tool 形态被本项目红线明确不采纳。
4. **财务地基口径**:移动加权成本账随库存流水同事务推进(非事后报表反推),退款勾稽/结算勾稽双对账闭环——这是利润"准"的地基,对标开源三家中最扎实。
5. **安全基线**:凭证 AES-256-GCM、密钥无默认值启动强制、脱敏出口唯一、SMTP 授权码 sys_config 范围例外三道防线。
6. **工具链沉淀**:erp-codegen 八件套 + 状态机守卫测试生成器 + 前端 gen:page/api:sync + mapper XML 真库验证脚本——"同一路径第二次出现即沉淀生成器"的机制本身是对标中没有的。
7. **文档与决策记录**:docs/01~10 全链路设计文档 + devlog 31 篇拍板归档,可追溯性高于全部对标。
