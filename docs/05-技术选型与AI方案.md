## AI 方案

### 版本对齐(为什么最终落 Boot 4.x)

> 2026-09 更新:应"要上 Spring AI Alibaba 2.0 + AgentScope 2.0"的要求,从 Boot 3.5 方案切换到 Boot 4。经 Maven Central 核实(2026-09-02 初核,2026-09-06 三期开工复核):

| 组件 | 版本 | 状态 | 说明 |
|---|---|---|---|
| Spring Boot | 4.0.6(4.0 线最新) | ✅ GA | 4.1.0 预计 2026-11,不抢跑 |
| Spring AI | 2.0.1 | ✅ GA(09-06 复核升级) | 2.0 线 = Framework 7 / Boot 4 世代;victools 须钉 5.0.0(JsonSchemaGenerator 依赖,见根 pom 注释) |
| Spring AI Alibaba(BOM) | 2.0.0-M1.1 | ⚠️ 里程碑 | 含 agent-framework / graph-core / studio / sandbox;graph-core 已投产,GA 后升 BOM 即可 |
| AgentScope Java(starter) | 2.0.2 | ✅ GA(09-06 复核升级) | 四期 agent 双角色已投产(SUPPORT/OPS);直依赖 victools 4.38.0 参与仲裁,已钉版处理 |
| MyBatis-Plus | 3.5.17 | ✅ GA | boot4 专用 starter |

结论:**SAA 2.0 / AgentScope 2.0 都构建在 Spring AI 2.0 之上,而 Spring AI 2.0 只支持 Boot 4.x,所以上它们 = 上 Boot 4**。2026-09-06 三期开工时已按复核结果升级(Spring AI M5→2.0.1、AgentScope RC5→2.0.2,只动根 pom 三个 version 属性,零代码改动验证了当初的升级路径设计)。剩余 GA 关注点:SAA GA 与 Boot 4.1 GA(预计 2026-11)。

### 框架分层关系

```
              ┌──────────────────────────────┐
   四期已启用 → │ AgentScope Java 2.0(2.0.2 GA) │  agent 双角色 SUPPORT/OPS(工具零复制桥接)
              ├──────────────────────────────┤
   三期已启用 → │ Spring AI Alibaba 2.0(M1.1)  │  graph-core 工作流:异常监控/补货/采购/文案/选品
              │                              │
              ├──────────────────────────────┤
   基座(必选) │ Spring AI 2.0(2.0.1 GA)      │  ChatClient/@Tool 自然语言查询、chat 双通道
              ├──────────────────────────────┤
              │ Spring Boot 4.0.6             │
              └──────────────────────────────┘
```

- **Spring AI Alibaba**:不是替代 Spring AI,是**构建在其之上**的增强(通义/DashScope starter、Graph 工作流编排、Nacos 集成)。2.0 线的重心是 agent-framework + graph-core,`spring-ai-alibaba-graph-core` 已投产(五条工作流:Anomaly/Replenish/Purchase/Copywriting/Selection,母本见 docs/08 条目 15);
- **AgentScope Java**:阿里开源多Agent框架,`agentscope-spring-boot-starter` 已投产——SUPPORT 客服(tools/ 四类全量只读)+ OPS 运营(白名单工具),Spring AI @Tool 经 SpringAiAgentToolBridge 桥接为 AgentScope AgentTool,工具逻辑单一来源零复制。

结论:**基座 Spring AI 2.0(2.0.1 GA),模型 OpenAI 兼容接口按需切换(DeepSeek 便宜 / 通义 qwen 稳 / GLM 备用);三期/四期 AI 已分批落地,版本升级路径已被实证(09-06 升级只动根 pom 三属性)。剩余关注:SAA GA 后升 BOM、Boot 4.1 GA 后再评估。**

### AI 落地清单(对应 erp-ai 模块)

1. **@Tool 查询工具**(三期):OrderTools/GoodsTools/InventoryTools/RefundTools/PurchaseTools 等,只读查询,参考启航的 11 个 Tool 划分;✅ 落地(tools/ 四类只读 + SpringAiAgentToolBridge 桥接);
2. **运营异常监控**(三期):定时任务采样业务指标 → LLM 分析 → 分级推送(高优飞书/钉钉,低优站内);✅ 落地(AnomalyWorkflow 两段式,工作流母本);
3. **RAG**(四期+):一期不上向量库;文档知识库需求出现时用 pgvector(和 MySQL 并存无运维负担);未做;
4. **安全红线**:AI Tool 只开放只读查询接口,不赋予写库能力;SQL 由 Tool 方法内固定,不让模型自由拼;✅ 执行中(铁律);
5. **建议闭环**(三期):AI 产出一律落 `ai_suggestion` 建议表(待确认/已采纳/已忽略),人工确认后走正常业务接口——表结构见 docs/03 §7;采纳率回流用于评估与调优提示词;✅ 落地(adopt/ignore 状态机 + 守卫测试);
6. **两段式异常检测**(三期):规则引擎先筛(阈值类指标免费、可解释)→ LLM 只对可疑样本评分分级(OmniTrade RuleEngine→AIScorer 模式),避免每周期全量调 LLM;✅ 落地;
7. **会话持久化**(三期):`ai_chat_session` / `ai_chat_message` 落库(审计 + 多轮上下文),参考启航 ai_conversation_history 与 OmniTrade chat_session/chat_message;✅ 落地(chat 双通道);
8. **AI 工作流族**(三期):补货 Replenish / 采购建议 Purchase / 文案生成 Copywriting / 选品 Selection,全部照 AnomalyWorkflow 母本变体;✅ 落地(2026-09-07~08);
9. **Agent 双角色**(四期提前):SUPPORT 客服 + OPS 运营(AgentScope 2.0.2);✅ 落地(2026-09-07)。

> AI 编码规范(占位模式 / @Tool 划分 / 提示词集中 / 两段式实现约束)见 docs/07 §9;建议闭环红线见 docs/07 §7。

## 演进预案

| 触发条件 | 动作 |
|---|---|
| 单表 > 5000 万行(订单/流水) | 分表(sharding 按商户/时间) |
| 拉单店铺 > 50 或平台故障影响前台 | erp-worker 拆独立进程(模块已隔离,改部署即可) |
| SAA GA / Boot 4.1 GA(预计 2026-11) | 升级根 pom version 属性,跑全量回归(Spring AI/AgentScope 升级路径已于 09-06 实证) |
| 多团队并行开发冲突频发 | 按现有模块边界拆服务(此时拆,成本最低) |
