## 交付内容

### ① 限流真值动态校准通道(#3,docs/04)

- **RateLimitObserver**(gateway 包,函数式接口):SpApi*Client 对限流器零感知,只上报
  `x-amzn-RateLimit-Limit` 响应头原值;装配点 `AmazonAdapterConfig.observerOf()` 绑定平台,guard 缺位传 null。
- **PlatformRateGuard 扩容**:`observeRateLimit` 解析响应头(缺头/解析失败/非法值静默忽略——校准是增强
  不绑架调用),按 platform+bucket 收紧 interval:**多 endpoint 保守合并取最小速率,与配置取更保守者**;
  校准刷新后该桶已下发的 setRate 按 key 前缀失效,下次 acquire 重下发(原「每 JVM 一次」机制按校准动态打破);
  interval 封顶 120s 防异常小值拉爆调度。
- **四个 SpApi*Client 全部挂观测**(orders/finances/reports/inbound):`body()` 改 `toEntity()` 取响应头,
  成功与失败(429 亦携带限流头)都上报;confirmShipment 走 WRITE 桶、其余 PULL 桶;
  S3 文档下载不走此口径(鉴权在 URL,无 SP-API 配额语义)。
- 单测:PlatformRateGuardTest 扩 5 例(收紧生效/不放宽/多 endpoint 合并/失效重下发/非法值忽略)。

### ② AftersaleRefundPullJob 售后拉单接线(#3)

- 仿 OrderPullJob(窗口游标)+ SettlementPullJob(总开关)形态:**erp.adapter.refund-pull.enabled 默认 false**,
  关时零噪音直接返回(兑现「接早了会对假报文产生 pull_log 失败噪音」的 #12/#3 拍板;true 不改代码即启)。
- 窗口 = 上次成功 window_end 左叠 WINDOW_OVERLAP_MINUTES(退款事件与订单同「更新时间窗」模式,
  Finances PostedAfter/Before 记账时间),首次拉取回溯 erp.pull.first-pull-days;间隔默认 1 小时。
- 落库走 saveUnifiedRefund 唯一入口(uk_shop_platform_refund 幂等),会话店铺回填防报文内脏值;
  单店失败隔离 + pull_log 必记 + 连续 3 次站内告警 + Redisson 店铺锁,MDC traceId 纪律同款。
- 单测 7 例(默认关零噪音/窗口游标/首拉回溯/店铺回填/会话失败记 log/失败隔离不推游标/阈值告警)。

### ③ #35 SP-API Fulfillment Inbound 客户端(fba-shipment V2)

- **PlatformClient SPI 三 default 方法**(非 FBA 平台默认 UOE):createInboundShipmentPlan /
  putTransportContent / pullInboundShipments(getShipments + getShipmentItems 装配)。
- **平台中立模型四 record**(platform 根包,PlatformShipment 同款 @Builder 防参错位):PlatformAddress /
  PlatformInboundPlanRequest / PlatformInboundShipment(行级 quantityPlanned/Shipped/Received 三语义一型三用)/
  PlatformTransportContent(partnered 两态,联调拍板)。
- **SpApiInboundClient**:仿 SpApiOrdersClient 形态(SigV4 签名 POST/PUT body 参与载荷、查询串取签名器
  规范串禁二次拼参、LWA 走 x-amz-access-token 头);ShipmentIdList 官方单查上限 20 分批;
  NextToken 翻页防御上限 50;异常只透 HTTP 状态码(docs/07 §7)。
- **AmazonInboundTranslator**:报文翻译零业务 if(docs/07 §8),必填字段缺失即拒禁静默;
  fixture 为官方 fulfillment-inbound-api-model schema 推导样例(同 #3 预备骨架口径,真报文到位后 --force 校准)。
- **PlatformGateway 装饰**:计划生成/板箱回传走 WRITE 桶,收货拉取走 PULL 桶;AmazonClient 覆写三方法
  (requireLwaToken 校验收敛 + currentAwsCredentials 复用)。
- 单测 15 例(SpApiInboundClientTest 9:三方法请求形态/签名头/翻译/分批/限流头观测/400 只透状态码/
  空单零请求/空计划行拦截;AmazonInboundTranslatorTest 6:计划/状态/对账行翻译/请求体两态/IsSuccess/缺必填)。

### ④ 顺手修复:PlatformGateway 缺 pullSettlements 装饰缺陷

- 装饰器未覆写 `pullSettlements`,调用落到接口 default 抛 UnsupportedOperationException,
  被 SettlementPullJob 的 catch(UOE) 静默吞掉——**结算开关 erp.adapter.settlement-pull.enabled 打开也永远空转**。
  已补覆写(BUCKET_PULL 装饰),PlatformGatewayTest 断言补位。
