## 交付内容(零 DDL)

- **后端订阅端点**:`POST /api/system/notifications/subscribe`(erp-system)——用 POST+JWT 而非原生
  EventSource,因为 EventSource 带不了 Bearer,前端 fetch 手解流(同 chat/agent SSE 先例)。
- **NotificationSseRegistry**:进程内连接注册表,同用户多 tab 上限 5 个,踢最旧。
- **NotificationSseService**:监听 `NotifyPushedEvent`(AFTER_COMMIT + fallback,与 Webhook/Mail 通知渠道
  同口径),全量扇出不按用户过滤;推帧 JSON `{notifyType,title,content,bizType,bizId}` + 30s 心跳。
- **NotifyPushedEvent 扩容**:加 bizType/bizId 两参(三参构造保留,Webhook/Mail 渠道不受影响)。
- **开关与超时**:`erp.notify.sse.enabled` 默认 true,关闭=订阅端点 404 前端自动降级轮询;
  `spring.mvc.async.request-timeout: -1` 防 Tomcat 默认 30s 异步超时杀空闲 SSE 连接。
- **前端**:NotificationApi.subscribe(postSse,sse.ts 加可选 AbortSignal 向后兼容)+
  notification store 双通道状态机——SSE 健康时挂起轮询、断开恢复轮询兜底,指数退避重连
  (1s×2 封顶 30s,抖动 ±20%);页面隐藏双通道暂停,回前台即连。
