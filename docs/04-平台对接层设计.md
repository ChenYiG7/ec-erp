## 分层

```
erp-worker / erp-api 拉单调度
        │  调用
        ▼
PlatformGateway(限流 #3 已落地;重试/日志二期)          ← 横切层
        │
        ▼
PlatformClient SPI(接口)  ◀── AmazonClient / TaobaoClient / DouyinClient / ShopeeClient ...(每平台一个 @Component)
        │  翻译
        ▼
UnifiedOrder / UnifiedProduct / UnifiedRefund     ← 统一领域模型
        │
        ▼
erp-order / erp-goods / erp-aftersale 落库
```

## 职责边界(重要)

| 关注点 | 归属 |
|---|---|
| 平台报文 ↔ 统一模型翻译 | 各 adapter(PlatformClient 实现) |
| Token 获取/刷新/加密存储 | erp-shop 授权中心(adapter 只消费 ShopSession) |
| 限流、重试、熔断、拉取日志 | PlatformGateway 横切层(装饰 PlatformClient) |
| 拉取调度(定时、时间窗、游标) | erp-api @Scheduled(一期)/ erp-worker(二期) |
| 幂等落库 | erp-order 等业务模块(唯一键 + upsert) |

adapter 内出现 if (business) 即为防腐失败,回退重构。

## 拉单策略

1. **增量拉取**:按 `更新时间` 窗口拉取(**必须按平台侧"更新时间"而非"下单时间"**,否则已拉订单的状态回传/取消会丢——启航 ORDER 与 ORDER_UPDATE 分游标就是为此),窗口 **向左重叠 5 分钟** 平台时钟漂移,靠唯一键幂等去重;窗口内分页按平台语义翻页(Amazon SP-API = NextToken,≤100/页,已随 #3 落地);
2. **游标管理**:每个 shop × biz_type 记录上次拉取水位(pull_log 表),断点续拉;
3. **新店铺初始化**:全量拉取近 90 天(配置键 `erp.pull.first-pull-days`,默认 90;各平台上限不同,adapter 内截断);
4. **优先级**:国内平台多走推送/Webhook 可降低轮询频率;跨境 SP-API 类以轮询为主(注意平台配额,亚马逊每分钟调用预算有限,Gateway 按 shop 限流;配额窗口状态要**持久化到 Redis/表**——wimoor 用 t_amz_api_timelimit 表跟踪各 endpoint 配额,防重启丢状态,值得参考;
   2026-09-04 已落地 `PlatformRateGuard`:Redisson RRateLimiter 令牌桶,key=`erp:ratelimit:{platform}:{bucket}:{shopId}`,窗口状态在 Redis 防重启丢、多实例天然合并;间隔 `erp.rate.{platform}.{bucket}-interval-ms` 可配,bucket 分 pull/write 两桶(拉单与平台回写互不挤占),
   总开关 `erp.rate.enabled`(false 整体直通);Redis 故障 fail-open 降级,配额等待超时 fail-closed 抛 429;SP-API 真值随 SigV4 实调按响应头校准);
5. **失败处理**:单店铺失败不影响其他店铺(线程池隔离 + try/catch 全包),失败记 pull_log,连续失败 3 次升级告警
   (站内通知 #14 已落地:`shouldAlertContinuousFailure` 恰达阈值轮次告警一次,连续段不重复推;邮件/短信/IM 为后续渠道);
6. **可观测**:每次拉取记 pull_log,含耗时 `duration_ms` 与触发方式 `pull_way`(JOB/MANUAL),慢店铺、高频失败一目了然(参考启航 o_shop_pull_logs 的 duration 字段)。

## 授权中心(erp-shop)

- Token 落库**必须加密**(AES-GCM,密钥走环境变量,禁入代码/配置文件);
- **密文规格(TODO#2 已落地)**:AES-256-GCM,随机 12 字节 IV,tag 128 bit,存储格式 `Base64(IV ‖ 密文+tag)`;
  密钥 = 环境变量 `ERP_TOKEN_KEY`(32 字节标准 base64,无默认值,缺失/非法启动即失败);
  加密写入唯一入口 `ShopService.createShop/updateShop`(含掩码回传防护:GET 脱敏值原样提交时忽略覆盖),
  解密装配唯一入口 `ShopService.getShopSession`;日志/返回体/异常消息禁出现明文或密文,凭证字段 `@ToString.Exclude`;
- OAuth 回调(#3 已落地):`GET /api/shops/oauth/callback` 浏览器直跳免 JWT(SecurityConfig 放行);
  state = AES-GCM 加密 `用途|shopId|到期ms`(复用 ERP_TOKEN_KEY,10 分钟 TTL,免 Redis 依赖),校验即解密、伪造即拒,
  LWA 授权码单次有效兜重放;换码入库走 `applyOAuthToken`(与刷新同走加密链路,refreshToken 空不覆盖);
- 刷新策略(2026-09-04 定案):读取时检查 `token_expire_at`,**过期前 10 分钟**统一刷新;刷新失败告警并停该店铺拉单
  (弃「提前 1 天」旧口径:Amazon LWA access_token 有效期 1 小时,提前 1 天=每次拉单都刷新,浪费且易触发平台频控)。
  2026-09-04 已落地:收口 `ShopService.getShopSession`(授权中心唯一装配出口,拉单消费方零感知);
  跨实例防双刷新 = DB CAS(`WHERE token_expire_at <=> 旧值` 条件更新即守卫,LWA refresh_token 不轮换双跑无害);
  刷新失败走 pull_log 连续失败告警;adapter 未接入静默跳过(不产生失败噪音,#4 口径);
- 国内平台差异:部分平台无刷新 Token、部分(如抖店)需代店铺申请,差异封装在 `exchangeToken/refreshToken` 实现内。

## 统一状态机

平台状态 → 统一状态翻译表放在各 adapter 内,保持枚举一致:

```
WAIT_PAY → WAIT_SHIP → SHIPPED → COMPLETED
                ↘ CANCELLED / CLOSED(退款关闭)
```

订单状态变更只允许由"拉单同步"和"本系统操作"两条路径产生,禁止旁路 update。

## 发货回传

- 国内:`uploadTracking` 回传运单号 + `fetchWaybill` 电子面单取号;
- 跨境 FBA:不回传(平台自己履约),只对账;
- 海外仓/物流商:调物流商 API 取号后回传平台。

## 国内 vs 跨境差异速查

| 环节 | 国内 adapter 要做的 | 跨境 adapter 要做的 |
|---|---|---|
| 订单 | 推单/轮询,人民币,简化收件人 | 轮询,多币种+汇率,国家/州/邮编,识别 FBA 订单 |
| 商品 | 类目属性较复杂 | 变体(asin/parentAsin)为主 |
| 售后 | 退款单同步 | 退货 + FBA 退货(退到亚马逊仓库,不产生实物流) |
| 回传 | 面单取号+运单回传 | 无(FBA)或物流商取号+回传 |

## 一期平台建议

- **跨境先跑**:Amazon SP-API(注册门槛低——有专业卖家账号即可,LWA 授权文档完善);
- **国内先跑**:抖店/拼多多(资质门槛相对低);淘宝需要 ISV 资质,门槛最高;
- **前置依赖**:AppKey 申请周期 1-4 周不等,动工前先提交申请,开发期用平台沙箱环境联调。
