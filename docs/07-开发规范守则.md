## 1. 项目裁剪与偏差

- **领域模型【2026-09-03 补全写侧收口"entity 不对外";同日 CQRS 分包:入参按读写拆 request/command 与 request/query,出参归 response,XxxVO 更名 XxxResponse】**:实体不加后缀(与现有一致:SysUser/Shop),只活在 Mapper/Service 层,禁止直接作为 HTTP 收发模型(mass assignment、脱敏裸奔、契约=表结构三宗罪);
  写侧入参 `request/command/XxxSaveRequest`:`@RequestBody` + `@Valid` 落点,创建/更新共用一套,id 由路径携带不入参,id/created_at/updated_at 及服务端管理列(如 merchant_id)不得出现,映射用显式 `toEntity()`;字段差异大的域再拆 `XxxCreateRequest`/`XxxUpdateRequest`,默认不拆;command 类继续增多再按领域分子包(如 request/command/user);
  读侧入参 `request/query/XxxQuery`:继承 PageQuery,GET 查询串自动绑定,过滤条件字段加在这里(无过滤条件的简单分页可直接用 PageQuery,不建类);
  出参 `response/XxxResponse`(原 XxxVO):只声明允许对外的字段,敏感/内部字段**不建进 Response 即编译期封死**,映射用显式 `XxxResponse.from(entity)`(禁反射拷贝,漏字段要编译期可见);演进点:复杂列表/详情可由 Mapper 联表直接投影到 Response(轻量 CQRS 读模型,不走 entity 中转);
  CQRS 语义锚定:command 只写(POST/PUT/DELETE)、query 只读(GET);写路径 SaveRequest→toEntity→entity,读路径 entity→from/联表投影→Response,两侧模型互不复用;
  跨模块传输 `XxxDTO`(与 HTTP 模型无关,别混用);
  豁免:dict/brand 纯配置域可暂以 entity 直连(与 §2.1 整域收口同源——确不生长的域不加层,长出第一条规则建 Service 时一起 Response 化);存量域按 shop→user→goods 逐域翻新(TODO.md #8),新域一律 codegen 八件套直接生成;
- **模型可变性分级【项目,2026-09-04 定版】**:各层模型"可不可变"按框架约束定档,反对两个极端(全可变散播 / 全不可变教条)——
  ①Entity:**默认 @Data+@Builder+双构造【2026-09-04 起,全量 24 个 entity 已挂】**——@Data 保留(resultType 反射映射、updateById null-skip 读 getter、`Entity::getX` Wrapper 方法引用都依赖 setter),@Builder 供纯构造装配位(建行/翻译/调用方入参装配/toEntity),@NoArgsConstructor+@AllArgsConstructor 保无参构造(MP/存量不受影响);**加是默认的,用是场景判断**:builder 只许在纯构造位,set 端保留给下方白名单(读改写/写前回填/单字段回填),禁把 entity 当跨层可变 DTO;
  ②Query:**继承例外,保持 class extends PageQuery**(record 不能继承类,钳制分页在其上);PageQuery 重构时再议;
  ③Response:**record + @Builder**,读侧不可变;`from(entity)` 用 builder 命名传参(防相邻同类型字段错位,如 id/merchantId 相邻双 Long);"构造后补字段"用 wither 副本(例:`ShopOrderResponse.withItems` / `LoginResponse.withToken`),禁为补一个字段回退可变模型;
  ④SaveRequest:**record + @Builder**;@Valid 约束注解放组件上(LoginRequest/SkuBindRequest 已验证链路);**含敏感字段的 record 必须手写 toString 脱敏**——record 自动 toString 携带全部组件,且 Lombok @ToString.Exclude 在 record 上不生效(ShopSaveRequest 凭证三字段、SysUserSaveRequest.password 即此写法);
  ⑤业务层装配:**非白名单的"new + 长串 set 一次性装配"一律 builder/构造器/record**(adapter 翻译、pull_log 行、响应组装);entity 已默认挂 @Builder(见①),装配直接用,无需再逐个补注解(toEntity 两种写法均合法:存量 set 链随域翻新演进,新生成域一律 builder 链);
  **setter 白名单(超出即视为可变态泄漏)**:toEntity/from 显式映射、写前回填(id/服务端管理列)、安全加工唯一入口(加密/脱敏)、库存读改写(before/after)、Service 层内部 entity 装配(组树等,不出层)、MP `Page.setRecords`(框架对象);
  codegen 八件套已按此分级产出(2026-09-04 起),存量域随 TODO.md #13 翻新;
- **Service 方法命名**(MP/社区惯例,与 MP Mapper 命名天然对齐):单个 `getXxx` / 列表 `listXxx` / 统计 `countXxx` / 新增 `save`·`insert` / 删除 `remove`·`delete` / 修改 `update`;
- **金额红线(含《手册》偏差声明)**:《手册》要求货币以最小货币单位整型存储;本项目为跨境多币种场景,统一 **DECIMAL(12,4) + BigDecimal**(汇率 DECIMAL(12,8)),**禁 double/float**;平台原始报文若为最小单位整数(如美分),由 adapter 翻译成元后落库;
- **时间**:统一 `LocalDateTime` + `DateTimeFormatter`;平台 epoch/时区字符串只在 adapter 内翻译;前后端传输统一 `yyyy-MM-dd HH:mm:ss` 字符串或毫秒时间戳;
- **禁魔法值**:状态码/类型码一律枚举或常量(订单状态、flow_type、match_status 已有枚举/字典的,严禁再写字面量);常量按职能归类(`RedisKeyConsts` / `PullConsts`…),禁一个 `Consts` 装天下;复用层次:跨模块共享进 erp-common,单类私有别外扬;
- **并发要点与锁选型【项目,2026-09-04 定版】**:先分两类再选机制——**正确性锁**(不加即数据错误:超卖/双刷,必须落在共享状态所在地)vs **效率锁**(不加仅浪费:重复拉单,幂等已是最后防线,锁选便宜的):
  ① 共享状态在 DB 行 → **一条原子 UPDATE**(行锁天然串行化,affected=0 即拒绝),如库存扣减;不引应用层锁、不加 version 列(冲突即重试,不如原子 UPDATE 直接),禁 selectOne→Java 算术→updateById 的 check-then-act;
  ② 临界区含外部 IO(平台 API,分钟级、时长不可控)→ **禁 DB 悲观锁 FOR UPDATE**(长事务占连接池)与**手写 Redis setnx**(超时误删他人锁/无续期双跑);
  ③ 效率锁的跨进程形态一期即定型 **Redisson per-key**(2026-09-04 二次定版,收口 `LockService.tryAcquire`,锁被占跳过不排队)——Redis 已在运行栈,不为锁新增中间件;且二期多实例/灰度期进程内锁会**静默失效**(不报错即防不住,重复拉单撞平台限流风控),迁移动作恰落在系统最脆弱的窗口;拉单防重入 = 单线程调度器(进程内第一道)+ 店铺级 Redisson 锁;Redis 故障按 `erp.lock.fail-open` 降级(一期默认 true:单实例无第二进程,无锁照跑靠 uk 幂等兜底;二期多实例置 false:宁停拉,不重复拉撞风控);二期吞吐不足再上 **worker 分片**(分片管吞吐、锁管互斥兜底,二者并存);Token 刷新 single-flight(轮换型 refresh_token 平台)同走 LockService 不同 key(`lock:token:{shopId}`),全系统一套锁设施,不出现两套锁系统;
  ④ 线程池用 `ThreadPoolExecutor` 显式参数并命名线程(`pull-worker-{shopId}`);
- POJO 布尔**不加 is 前缀**(库 `is_xxx` ↔ 实体 `xxx`,MyBatis 映射经典坑,见 §12);
- **文件头注释【项目,2026-09-03 定版】**:每个 Java 文件在**最后一个 `import` 之后、类声明/类级注解之前**带统一文件头 `@author` / `@Date` / `@Description`,并与类注释**合并成一块**(原类注释内容即 `@Description`,不另起一块);无类注释的文件(如 Mapper)就地插入,`@Description` 回退填包名;`@Description` 多行时续行缩进 4 空格;模板唯一真相源为 `erp-codegen` 的 `CodeGenerator#fileHeader`——八件套自动生成;存量已于 2026-09-03 补齐(当时用一次性脚本完成,脚本已弃置),**禁大模型逐文件手写文件头**(格式漂移;少量手工文件参照真相源渲染或复制邻近文件头),批量迁移场景写临时脚本(CLAUDE.md 铁律 #8:同构批量修改走脚本,判断归 AI、执行归程序);
- **注释 + TODO(编号) 约定【项目强化】**:复杂逻辑/AI 只写 `TODO(编号)` + 实现指引,**不实现**;新编号同步登记 TODO.md,代码注释与清单一一对应;**禁无编号裸 TODO/FIXME**;占位代码抛 `UnsupportedOperationException` 封死,防半成品产出脏数据;方法内单行注释在被注释语句上方另起一行 `//`,与其半吊子英文,不如中文把问题说清楚。

## 2. 应用分层与模块边界

### 2.1 《手册》"应用分层"在本项目的实体化

《手册》五层(终端/Controller/Service/**Manager**/DAO)出自"应用分层"一节【参考级,非强制】;Manager 层的职责"对第三方平台封装"在本项目实体化为 **erp-platform-sdk(PlatformClient adapter)**;"通用能力下沉、组合 DAO、缓存方案"仍归各域 Service。**下表职责切分与后续 bullet 均为【项目】实体化**——《手册》原文无"Controller 可/不可直接调 DAO"条款,允许与否是本项目的选择。

| 层 | 只做 | 禁止 |
|---|---|---|
| Controller | 参数校验(@Valid)、调 Service/Mapper、Result 包装 | 业务规则、多表操作、try/catch 吞异常 |
| Service | 业务规则、事务边界、跨表编排 | 平台 API 调用直连(走 platform-sdk) |
| Mapper | 通用 CRUD + 自定义 SQL(XML/注解) | 业务判断 |
| Entity | 映射表结构 | 直接对外返回(含敏感字段) |

- 统一写法【项目,依据 MP 3.5.9 移除 IService 的版本事实,**非《手册》条目】**:**Mapper 做通用 CRUD,Service 只装业务逻辑**(plain @Service + `@RequiredArgsConstructor` 构造注入);**禁止引用 MP 泛型 Service 基类**(IService/ServiceImpl 已移除,替代品 IRepository 也不用——写法不受版本演进影响);
- 无业务规则的简单 CRUD 允许 Controller 直接用 Mapper;一旦出现校验/多表/事务,**必须下沉 Service**【项目;引申自《手册》Web 层"不复用的业务简单处理"——是裁剪授权,不是手册原文】;
- **整域收口判定【项目,2026-09-03 由"敏感表例外"泛化】:按域二选一,禁止域内混合**——
  域内出现过任一业务规则(= 该域已有 Service),或属敏感表(凭证/密码类)、复杂逻辑表 → **该域全部接口走 Service,Controller 禁止注入该域 Mapper**;
  确无 Service 且可预见不生长逻辑的纯配置表(dict/brand)→ 允许直连,但**长出第一条规则即建 Service 整域下沉**;
  现状:shop/product(sku)/category/user/role/menu 域已收口,dict/brand 直连合规;
  为什么按域不按接口:增量混合(如 role 的 delete 走 Service、page 直连)会让规则持续在 Controller 生长——Controller 每多一行非装配代码就离业务层近一步;
- **接口文档【项目,2026-09-03】**:springdoc 3.x(Boot 4 专用线,自带 Swagger UI)——每个 Controller 必标 `@Tag`(中文组名),每个接口必标 `@Operation`(中文 summary,特殊语义写 description);
  预览 `/swagger-ui.html`,规范 `/v3/api-docs` 供 Apifox 订阅;生产 `springdoc.api-docs.enabled=false` 关闭(SecurityConfig 已放行文档路径,不在 /api 红线内);实体字段 `@Schema` 按需补,不强求;
- 对外返回 Response(docs/07 §1),entity 不再直接出 Controller;密码/凭证等敏感字段**不建进 Response 即物理隔离**,语义性脱敏(如密文前 6 位掩码)收口在 Service 读出口(参照 ShopService.pageShops/getShopById、SysUserService.pageUsers/getUserById);
- Service 无状态:禁在 Service 存可变成员变量(单例被并发共享,必出脏数据)。

### 2.2 模块边界(违反即返工)

```
erp-common ←── 任何模块
erp-contract ←── 跨域契约消费方(只依赖接口):erp-goods(GoodsReferenceApi 删除引用校验)、
  erp-shop(GoodsSkuApi bind 存在性校验 + ShopReferenceApi 店铺删除引用校验)、
  erp-purchase(#10 起:GoodsSkuApi/WarehouseApi 存在性校验 + InventoryChangeApi 动库存唯一通道——
  业务域动库存必须经 InventoryService.change(铁律 4)但禁横向依赖 erp-inventory(铁律 2),契约中转)、
  erp-warehouse(#7 起:WarehouseApi 仓库删除引用计数)、
  erp-fulfill(#11 起:ShopOrderApi 发货视图/订单状态条件推进 + WarehouseApi 出库仓存在性 + InventoryChangeApi 出库动账);
  实现统一收口 erp-api(GoodsReferenceApiImpl/GoodsSkuApiImpl/ShopReferenceApiImpl/InventoryChangeApiImpl/
  WarehouseApiImpl/ShopOrderApiImpl 编排胶水);写侧契约(InventoryChangeApi)无自建事务,同事务语义由调用方 @Transactional 保证
  (实现委托 @Transactional(REQUIRED) 方法即加入调用方事务)。
  ⚠️ 装配断环【2026-09-05】:域 Service 注入契约接口一律 **@Lazy**(显式构造器参数标注,不用 @RequiredArgsConstructor——
  Lombok 不会把 @Lazy 拷到构造参数上,注解形同虚设)——契约实现反向注入各域 Service,而"引用计数/存在性校验"跨域成对
  (goods↔shop、warehouse↔purchase),急切装配必成构造环(Boot 默认禁循环依赖,allow-circular-references 对构造器注入无效);
  @Lazy 调用期才解析真实 Bean,与校验类依赖只在删除/绑定等写路径使用的时机吻合;构造签名不变,单测零感知
  ⚠️ 偏差声明【#10,2026-09-04】:erp-contract 引入 lombok(provided,仅编译期注解处理器,非运行时依赖)——
  契约命令模型(InventoryChangeCommand)@Builder 防调用方相邻同类型参数错位(§1 ⑤)
erp-platform-sdk ←── 调平台 API 的模块:erp-shop / erp-fulfill / erp-worker
erp-platform-sdk ←── Unified* 落库方:erp-order(2026-09-04 起;后续 erp-goods/erp-aftersale 同)——仅依赖 unified 模型作落库入参,禁止调用平台 API
全部业务模块 ──→ erp-api 聚合编排
```

- 模块间禁止:横向 @Autowired 对方 Mapper/Service、跨模块 join、复制对方实体类;
- 跨域调用一律在 erp-api 编排;同类编排重复出现 3 次,再议引入接口模块,不提前抽象
  (2026-09-04 首个例外:删除 SKU/SPU 引用校验 + bind 存在性校验按人工拍板提前引入 **erp-contract**——
  契约接口零依赖零实现,消费方依赖接口,实现 Bean 收口 erp-api;引用侧计数取数仍走各归属域 Service,不破坏域内收口);
- controller 只能出现在各模块自己包内;erp-api 只写配置与编排,不写业务;
- 新第三方依赖先登记进根 pom `dependencyManagement`,业务模块不得私自引入未登记依赖;
- AI 能力只进 erp-ai 单模块(OmniTrade 把 AI 拆成 9 个微服务是反面教材:能力内聚,部署形态才谈拆分)。

## 3. 异常与日志【项目部分】

- 业务错误一律 `BusinessException`(带 code 与可读消息),禁裸抛 `new RuntimeException()`;NPE 靠预检查规避,不靠 catch 兜;全局只兜底一次(GlobalExceptionHandler),**禁 catch 后不记不抛**(吞异常 = 数据静默丢失);
- 事务回滚统一 `@Transactional(rollbackFor = Exception.class)`(默认只回 RuntimeException 的坑);禁 finally 里 return;
- 异常消息禁带敏感信息(凭证/Token,见 §7);方法可返回 null 必须注释说明场景;
- ERROR 必带上下文(shopId/orderId/skuId)与异常堆栈(最后一个参数),禁 `e.printStackTrace()`、System.out;
- info 只留关键链路:拉单(shop/type/window/数量/耗时)、发货回传、Token 刷新、AI 建议生成与采纳;
- **排障第一入口是 pull_log 等业务日志表,不是翻服务器日志**——观测字段落库时必须写全;同一失败连续 3 次必须升级告警(推通知渠道)。

## 4. 事务与一致性【项目铁律】

- 多表写必须 `@Transactional(rollbackFor = Exception.class)`,注解在 Service 层(参照 ProductService.createProduct);
- **事务内禁止**:平台 API 外呼、HTTP 请求、通知推送、文件上传——先落库,事务提交后再外呼(`TransactionSynchronization.afterCommit` / Spring 事件);
- 库存唯一入口 `InventoryService.change()`,同事务写 inventory_flow;任何模块不得直接 update 数量列;
- 订单/售后状态只允许两条路径产生:拉单同步、本系统显式操作;禁止旁路 update;
- 事务内禁混用多种数据存储(MySQL + Redis 写进同一事务无法保证一致——Redis 只做锁与缓存,不承载事务语义);
- 金额一律 DECIMAL(12,4) + BigDecimal;汇率 DECIMAL(12,8);时间 DATETIME + LocalDateTime(见 §1 偏差声明)。

## 5. 幂等与调度【项目】

- 平台数据落库一律靠唯一键 `(shop_id, platform_xxx_id)` upsert(`INSERT ... ON DUPLICATE KEY UPDATE` / MP saveOrUpdate),**不靠"先查后插"**(并发下必重复);
- 拉单游标:pull_log 最近一次成功 `window_end` 左叠 5 分钟;**ORDER 拉取必须按平台"更新时间"窗口**(按下单时间会丢状态回传,见 docs/04);
- 单店铺失败隔离:try/catch 全包 + 记 pull_log(**必含 duration_ms 与完整错误信息**);连续 3 次失败推通知渠道;
- 定时任务防重入 = 单线程调度器(进程内第一道)+ 店铺级 Redisson 锁 `LockService.tryAcquire`(写法见 §1 ③;2026-09-04 定版一期即 Redisson,Redis 故障按 `erp.lock.fail-open` 降级);禁手写 setnx;
- 批量写用 batch insert;循环单条 insert 超 100 条即重构;循环内查库(N+1)一律改批量 in 查询(in 元素 ≤ 1000)。

## 6. MySQL 数据库与 ORM

### 6.1 建表规约(与《手册》偏差已声明)

- 小数一律 `decimal`,**禁 float/double**;是否类字段 `is_xxx` TINYINT 1/0(实体侧去 is 前缀);状态类字段 `status` TINYINT + 注释写明枚举含义;
- varchar ≤ 5000,更长文本用 `text` 拆独立表;
- **偏差【项目】**:《手册》三字段 id/create_time/update_time,本项目统一 `id / created_at / updated_at`(一期已建库既成事实,新表沿用);时间戳两列**所有表必带**;
- 表命名 `业务_作用`,模块前缀与表名对齐(shop_/product_/shop_order_/inventory_…);库名与应用一致(erp);改字段含义必须同步改 COMMENT;
- 非负数字段 unsigned(新表执行,已建表不强改);允许适度冗余提速,但冗余字段必须不频繁改/不超长/不在唯一键上;
- 单表 > 500 万行或 > 2GB 才分表,预计三年到不了的量不预分表;触发线见 docs/05 演进预案;字符集统一 utf8mb4;
- **新表先在 docs/03 登记再进脚本**【项目】;一期核心表加列:改脚本 + 改 docs/03 + TODO.md 留 ALTER 语句。

### 6.2 索引与 SQL(项目要点)

- 业务唯一字段(含组合)必须建唯一索引——**本项目幂等的根本**(uk_shop_platform_order / uk_platform_seller / uk_sku_wh);
- 禁左模糊/全模糊搜索(确需再上 ES,现阶段不做);**禁外键与级联**(一致性在应用层保证;本项目脚本从未建外键,保持);禁存储过程;
- 数据订正(尤其删改)先 `SELECT` 确认再执行;`TRUNCATE` 不进生产代码;其余索引/SQL 细则按《手册》与 explain 执行计划。

### 6.3 ORM 映射(手册+MP 裁剪)

- 自定义 XML/联表查询:明确列名禁 `*`;复杂结果集必须 `<resultMap>`;参数一律 `#{}`,**禁 `${}`**(SQL 注入);
- MP 单表 CRUD 裁剪口径:实体字段=表字段驼峰映射,默认全列查询属预期,不算违反上一条;
- 更新必须带 updated_at(表上 `ON UPDATE CURRENT_TIMESTAMP` 兜底);
- **禁一个大而全的 update 接口**——按语义拆更新方法,防止并发互相覆盖;
- MyBatis-Plus 3.5.9+ 硬约束:必须 `mybatis-plus-spring-boot4-starter` + `mybatis-plus-extension` + `mybatis-plus-jsqlparser`(根 pom 已配,勿删);IService/ServiceImpl 已移除,统一写法见 §2.1。

## 7. 安全规约(项目红线)

- 隶属个人的页面/接口必须鉴权(`/api/**` 已由 TODO#1 JWT+RBAC 收口);
- 用户敏感数据脱敏展示(手机号/地址/Token——脱敏在 Service 读出口,不在 Controller);密码 BCrypt;SQL 参数只走参数绑定(Wrapper / XML `#{}`),禁字符串拼接;用户/外部入参必须校验长度/格式/范围(@Valid);
- 平台凭证 AES-GCM 加密落库,密钥从环境变量 `ERP_TOKEN_KEY` 或项目根 git-ignored `local.properties` 同名键读(env 优先;2026-09-05 与 ERP_JWT_SECRET 同规——原 System.getenv 直读绕过 Spring 属性源,local.properties 对其无效,已改占位符解析;禁入提交进库的配置文件);日志、返回体、异常消息禁出现明文凭证;换 `ERP_TOKEN_KEY` 后存量密文不可解(无信封加密,轮换 = 全部重新授权);CryptoService 对 null/空串透传(纯空格照常加密,blank 拦截在 ShopService);
- JWT【项目,TODO#1 落地后的坑与约定】:密钥环境变量 `ERP_JWT_SECRET`(≥32 字节,默认值仅限本地联调);角色列表在 JWT 载荷内,**改绑角色后重新登录生效**;JJWT 流式解码会忽略尾部悬挂 base64 字符——`JwtTokenService.parse` 已用严格解码器预校验拦截;Security 7 方法级鉴权拒绝发生在 MVC 内,由 GlobalExceptionHandler 统一转 403;
- **AI 永不直接写业务表**:产出一律落 ai_suggestion 建议表(待确认/已采纳/已忽略),人工确认后走正常业务接口;@Tool 只读,SQL 写死在 Tool 方法内,禁让模型拼 SQL;
- 支付/下单/回传类平台资源操作必须有防重入机制(幂等键 + 状态机前置校验)。

## 8. 防腐层(平台对接)【项目】

- adapter 内只做"平台报文 → Unified*"翻译;**出现 `if (业务)` 即防腐失败**,回退重构;
- 平台差异(状态枚举、币制、面单、FBA、时区)只允许存在于 adapter;业务层只见统一模型与统一状态机;
- Unified* 模型演进:只加字段不改语义;废弃字段 @Deprecated 保留一个版本再删;
- **raw_json 必存**(shop_order 等表),翻译出错可回溯重放;为外部对象建全套镜像表是过度设计(wimoor 为 1688 建了十几张表——只取核心字段成列 + raw_json 兜底);
- Token 获取/刷新只在 erp-shop 授权中心;adapter 只消费 ShopSession,不碰 shop 表;
- adapter 单测用真实报文样本(脱敏后)做翻译断言,不用 mock 报文自嗨。

## 9. AI 代码规范(erp-ai)【项目】

## 10. 单元测试

- **AIR 原则**:自动化、独立(用例间不依赖执行顺序)、可重复(不依赖外部环境与当前时间——拉单窗口/游标逻辑用固定时钟);测试类 `XxxTest` 只放 src/test/java;
- **必测清单【项目】**:金额计算、状态机流转、SKU 匹配、幂等 upsert、库存 change;adapter 翻译用真实报文样本;
- **MP Wrapper 急切解析坑【项目】**:`LambdaQueryWrapper.in()` 急切解析列元数据(无 MP 初始化即抛,列缓存未建),
  纯 Mockito 单测不可直测——规避:单测只走 eq/orderBy 路径,或只覆盖 in 之前的空集合短路分支(#5/#11/#8 三度验证);
  `LambdaUpdateWrapper.set()` 同款急切(#14 已读更新改实体 null-skip 的原因);生产代码为可测性绕开 in 属合理取舍,不必强写 in;
- 覆盖率目标【项目】:Service 层语句覆盖 70%,必测清单所在类 100%;提交前 `mvn -DskipTests compile` 必须通过,改动模块的相关测试必须跑过。

## 11. 设计补充

- Redis 缓存三问:与数据库一致性(先库后缓存失效)、穿透(空值缓存)、雪崩(过期时间打散);Redis 不承载事务语义(见 §4);
- 扩展优先组合/聚合;新增平台 = 加 adapter(扩展),禁改 Unified* 语义(见 §8);
- JVM 启动参数带 `-XX:+HeapDumpOnOutOfMemoryError`(OOM 留现场);三方依赖升级走 docs/05 版本表,禁散点升级。

## 12. 反模式对照表(发现即还债)

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 巨型 Service(>300 行 / 混多域) | 改不动、测不了 | 按业务能力拆进对应模块 |
| Controller 写业务/多表 | 事务失效、不可测 | 下沉 Service(整域收口见 §2.1) |
| 业务层 `if (platform == XX)` | 平台逻辑扩散全工程 | 收敛进 adapter |
| 旁路 update 库存/状态 | 账实不符、无法追溯 | 唯一入口 + 流水 |
| 先查后插防重 | 并发下重复数据 | 唯一键 upsert |
| 循环查库 N+1 | 慢查询拖垮拉单 | 批量 in 查询(≤1000) |
| 金额用 double/float 或 `new BigDecimal(double)` | 精度丢失、对不上账 | BigDecimal + DECIMAL(12,4) |
| catch 后只打日志继续跑 | 数据静默丢失 | 抛 BusinessException 或补偿记录 |
| 为外部对象建全套镜像表 | 表爆炸难维护(wimoor 1688 教训) | 核心字段成列 + raw_json 兜底 |
| 跨模块复制实体/Mapper | 数据口径分裂 | erp-api 编排 / 接口模块 |
| 半实现代码不封死 | 静默产出脏数据 | TODO 占位 + UnsupportedOperationException |
| 裸 TODO 无编号 | 技术债不可追踪 | TODO(编号) + 登记 TODO.md |
| 事务里调外部 API | 长事务、连接池耗尽 | 落库后 afterCommit 再外呼 |
| JSON 列当查询条件 | 全表扫描 | 要查的字段提列 |
| POJO 布尔加 is 前缀 | MyBatis 映射丢字段 | is_xxx 留在库,实体去前缀 |
| entity 直接当 API 收发模型 | mass assignment、脱敏裸奔、改表即破契约 | command/SaveRequest + query/Query + response/Response(docs/07 §1) |
| 反射拷贝(BeanUtil.copyProperties 式) | 漏字段/类型不匹配静默 | 显式逐字段映射(from/toEntity) |
| 业务层 `new` + 长串 set 一次性装配 | 中间可变态扩散、字段漏配无感知 | Builder/构造器/record 一次成型(分级白名单见 §1) |
| record 含敏感字段未覆写 toString | record 自动 toString 携带明文凭证/密码入日志 | 手写 toString 脱敏(@ToString.Exclude 在 record 上不生效) |

> 其余通用反模式(命名、格式、集合操作、线程池创建等)以《手册》原文与 p3c 扫描为准,本表不重复收录。
