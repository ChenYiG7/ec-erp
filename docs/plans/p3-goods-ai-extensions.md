## 一、背景与现状(2026-09-10 代码事实)

- **供应商比价**:`Supplier`(name/phone/contact/settleType/remark/status/deleted,无账期);`PurchaseOrderItem`(poId/skuId/quantity/arrivedQty/**purchasePrice**——采购价有落点但无"报价"语义,历史采购价散在订单行);**无报价记录表、无比价任何代码**;docs/02 §5"供应商报价记录、账期管理,二期 ❌"。
- **文案**:`CopywritingWorkflow`(graph/ 五工作流之一,Anomaly 母本变体);产出落 ai_suggestion 确认闭环;当前无平台风格参数维度。
- **listing 回填**:`PlatformClient` SPI 十方法中**无任何商品写方法**(pullProducts 只读);商品写=SPI 扩容级别改动。
- **选品**:`SelectionWorkflow` 评分工作流(权重当前为配置/代码内固定,无自调优);产出 ai_suggestion;无"选品→上架→销量"回流链路。

## 二、方案设计(每项=方向卡片,触发后细化)

### 2.1 供应商比价(前置=报价记录域)

- **依赖链硬事实**:比价的输入是"同 SKU 多供应商报价时序",当前无报价数据面。**第一步永远是报价记录域立项**(add-table:supplier_quote 表 sku_id/supplier_id/quote_price/currency/quoted_at/valid_until/moq 等,走 add-domain 流程)——这不是本计划能跳过的。
- 比价形态预设:查询面(SKU 维度多供应商报价对比+历史价格曲线)+ 采购建议联动(PurchaseWorkflow 产出可附"最低价供应商"提示,经 ai_suggestion 人工确认);**不做自动选商下单**。
- 采购价历史(订单行 purchasePrice)可作为报价的补充数据源(成交价 vs 报价对照),查询面一并出。

### 2.2 文案平台风格适配 V2

- 形态:风格参数表(sys_config 词表 or 配置 record——**拍板**:平台差异参数量大且演化快,建议配置文件/表而非硬编码):每平台 字符上限/标题结构/关键词密度/敏感词/hashtag 习惯/语言。
- 工作流改造:CopywritingWorkflow 的 prompt 装配处按目标平台注入风格参数(参数=数据,prompt 模板=代码);产出仍走确认闭环。
- 依赖:平台差异参数需预研录入(借 #24 差异登记表的预研成果,勿凭想象预填)。

### 2.3 listing 改写回填

- **SPI 扩容级改动**:`PlatformClient` 新增商品写方法族(如 `pushListing(session, UnifiedListingPatch)`),走 write-adapter skill SPI 变更流程(所有 adapter 同步实现/显式抛 Unsupported)。
- 链路:文案产出(ai_suggestion 采纳后)→ 生成 UnifiedListingPatch → **人工确认页二次确认** → adapter 推送 → 结果落 pull_log/回执表。
- 铁律 7 落地点:回填是写操作,**必须**人工确认触发,禁工作流自动回填;建议确认动作与 ai_suggestion adopt 合并为一个显式动作(adopt 即回填需二次确认弹层,拍板)。
- 编排归属:跨域(erp-ai 产出→erp-shop/adapter 执行)走 erp-contract 契约,实现收口 erp-api。

### 2.4 选品权重自调优

- 形态:回流闭环三段——①上架事件(选品采纳→真实上架,数据随 #24 上架动作产生);②销量回流(order_sales_daily 已有,按 SKU 关联);③调优器(简单回归/网格搜索对比"高权重组合的历史命中率",**非在线学习**,离线算+人工确认新权重)。
- 起步形态建议:先做**权重效果报表**(各权重分位与实际销量表现的对照),让人看得见再谈自动调——自调优前必有人工评估期。
- AI 产出纪律:调优建议落 ai_suggestion,权重变更人工拍板,禁自动生效。

## 三、开工路径(按触发项)

- ①报价域 add-table/add-domain → 比价查询面 → 采购建议联动提示。
- ②风格参数表 → prompt 装配改造 → 双平台 A/B 对比采纳率。
- ③SPI 方法族(write-adapter)→ 契约回填命令 → 确认页 → 回执与失败补偿。
- ④回流三段表 → 效果报表 → (效果被认可后)离线调优器+人工确认。

## 四、验收标准(按触发项)

- ①:比价面数据准确(报价 vs 成交价对照);采购建议附最低价提示且走确认闭环。
- ②:同 SKU 双平台产出风格差异可见;字符上限硬约束生效(超限截断/报警)。
- ③:回填后平台侧 listing 实际变更;失败可重试可追溯;全程有确认动作留痕(审计)。
- ④:效果报表数字与真库一致;调优建议含依据(数据引用),采纳后权重按拍板生效。

## 五、红线提醒

- **写操作人工确认**(铁律 7):比价选商、listing 回填、权重变更三个口子全部落 ai_suggestion/显式确认,禁自动化直达。
- SPI 扩容纪律:新方法全 adapter 同步(实现或显式 Unsupported),防腐翻译零业务 if,限流自动挂 PlatformGateway(写面 bucket=write)。
- 报价/比价金额 DECIMAL(12,4);跨币种比价先 resolveRate 折算,无报价不比(禁猜)。
- 文案风格参数禁入凭证类 sys_config 键;参数热更走 #18 口径。
